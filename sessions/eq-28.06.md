## TL;DR — what works right now

End-to-end audible EQ through Spotiglass, applying biquad filters in real
time:

```
Spotify Web Playback SDK (in WKWebView)
       ↓ system default output = Spotiglass EQ
SpotiglassEQDriver.driver (AudioServerPlugIn)
       ↓ DoIOOperation: EQDSP_Apply(biquads in-place)
       ↓ EQRouter_Push → lock-free SPSC ring
EQRouter's AudioDeviceIOProc on the chosen target device
       ↓
MacBook Pro Speakers (or whichever output the user picked)
```

Verified manually: preset switches (Flat / Bass Boost / Vocal / Treble
Boost) are audibly distinguishable when playing through MacBook speakers.

## Architecture overview

### Components

```
Spotiglass.app/Contents/MacOS/Spotiglass     (Swift, user-process, uid 502)
  ├─ AudioEqualizerEngine                    (orchestrates the EQ lifecycle)
  ├─ EqualizerHALPluginController            (install/route/forwarding)
  ├─ EQCoefficientPublisher                  (writes biquad coefficients)
  └─ EqualizerSettingsView                   (SwiftUI: toggles, picker, sliders)

/Library/Audio/Plug-Ins/HAL/SpotiglassEQDriver.driver
                                             (C/C++, runs inside coreaudiod, uid 202)
  ├─ SpotiglassEQPlugin.cpp                  (AudioServerPlugIn vtable)
  ├─ SpotiglassEQDSP.c                       (vDSP biquads, RBJ EQ cookbook)
  ├─ EQCoefficientReader.c                   (mmap'd seqlock reader)
  ├─ EQRouter.cpp                            (forwarding to real hardware)
  └─ EQCoefficientFrame.h                    (shared wire layout)
```

### IPC channels (all under `/tmp`, shared via fixed paths so no uid
mismatch between Swift uid 502 and `_coreaudiod` uid 202)

| Path | Purpose | Writer | Reader |
|---|---|---|---|
| `/tmp/com.isaaclins.spotiglass.eq.coeffs.v1` | 220-byte seqlock-protected `EQCoefficientFrame` | Swift `EQCoefficientPublisher.write` | C `EQCoefficientReader_Snapshot` |
| `/tmp/com.isaaclins.spotiglass.eq.target` | One-line UID of the device EQRouter forwards to | Swift `EqualizerHALPluginController.writeForwardingTarget` | C `TargetWatcherMain` (every 500 ms) + initial `StartIO` |
| `/tmp/com.isaaclins.spotiglass.eq.router.log` | Driver-side diagnostic log (remove for release) | C `EQR_log` | tail by humans |

### Why the design looks weird in places

- **In-driver forwarding via `AudioDeviceCreateIOProcID`.** A pure virtual
  output device has nowhere to send the buffer that `DoIOOperation`
  produces, so audio routed to Spotiglass EQ would be silent. The
  conventional fix (loopback device with an input stream) violates the
  project's "never expose an input scope" privacy constraint. So the
  driver opens its own `AudioDeviceIOProc` on the previous default
  output device and forwards the post-EQ frames there. Output-scope only;
  no input IOProc is ever created.

- **`EQRouter_Open` runs on a detached worker thread.** Calling
  `AudioObjectGetPropertyData` / `AudioDeviceCreateIOProcID` /
  `AudioDeviceStart` inline inside `StartIO` blocks forever, because
  coreaudiod is the very process servicing those calls and it's already
  busy with our `StartIO`. Off-IO-thread serialisation is required.

- **`GetZeroTimeStamp` is anchored to `mach_absolute_time()`.**
  coreaudiod uses the function to peg the device's sample-domain clock
  to the host clock; returning static zeros made it think the device's
  timeline wasn't advancing and tore down the IO thread with
  `kAudioHardwareStoppedError` (`'stop'`).

- **`DeviceIsRunning` is its own boolean (`gPlugin.ioRunning`), not
  derived from `coeffReader`.** Earlier the property handler returned
  `coeffReader != nullptr`; when the publisher file didn't exist yet
  (first launch), coreaudiod saw the device as never-running and
  refused to start IO.

- **Coefficient frame wire size is 220 bytes, not `sizeof(...)` = 224.**
  The C compiler adds 4 bytes of trailing alignment padding because the
  struct contains a `_Atomic uint64_t`. The Swift publisher emits only
  the declared fields (220 bytes). The reader's size check now uses the
  explicit `SPOTIGLASS_EQ_WIRE_BYTES` constant.

- **Router is kept alive across `StopIO`.** Each fresh client (a new
  `afplay`, a new audio session) triggers a Stop/Start cycle on the
  virtual device. Tearing down + re-opening the peer-device `IOProc` on
  every cycle drops the first ~200 ms of audio. The router now persists
  for the plugin's lifetime; `StopIO` only closes the coefficient
  reader.

## What we fixed tonight (commit `f543c85` + uncommitted picker work)

In rough order of discovery:

1. **macOS 26 coreaudiod only scans `/Library/Audio/Plug-Ins/HAL/`**,
   not `~/Library/...`. `EqualizerHALPluginController.defaultHALDirectory`
   now points to the system-scope path. Install fails over to a staging
   area + sudo cp hint when the directory isn't writable.

2. **`cp -R` invalidates code signatures** because the kernel checks
   `cs_mtime != mtime` and refuses to map the page. Use `cp -pR` to
   preserve the source mtime. Both the Makefile (`embed-driver`,
   `install-driver`) and the docs reflect this.

3. **`launchctl kickstart` is blocked by SIP on macOS 26.** Use
   `sudo killall coreaudiod` to reload the HAL plugin set.

4. **Apple Inc. Root CA must be explicitly trust-anchored** in the user's
   keychain for `codesign` to build the Apple Development cert chain.
   `scripts/setup-eq-driver-signing.sh` does this with sudo + the
   System keychain so it persists across reboots.

5. **The Apple Development private key needs `codesign:` in its
   partition list ACL.** Otherwise `codesign` gets `errSecInternalComponent`
   even with a valid chain. Setup script handles this too.

6. **`AudioServerPlugIn` callbacks can't call client APIs inline.**
   Solved with the detached `pthread_t` worker.

7. **`GetZeroTimeStamp` static zero issue** (described above).

8. **`DeviceIsRunning` vs `coeffReader` confusion** (described above).

9. **`getuid()` mismatch on /tmp paths** (described above).

10. **`sizeof(EQCoefficientFrame)` vs wire bytes** (described above).

11. **`previousDefaultOutputID` race when toggling EQ off then on**
    while Spotiglass EQ was already the default. Now falls back to
    `BuiltInSpeakerDevice`.

12. **Router torn down between StopIO/StartIO cycles** caused first-sound
    clipping. Now persists.

## Project policy / constraints (do NOT violate)

These were in the original `/goal` prompt and are LOAD-BEARING:

- **NEVER request Microphone / Audio-Recording permission.** No
  `NSMicrophoneUsageDescription`, no `AVCaptureDevice`, no
  `AVAudioEngine.inputNode`, no `AudioHardwareCreateProcessTap` /
  `CATapDescription`, no `kAudioObjectPropertyScopeInput`. The audit
  `scripts/eq-mic-permission-audit.sh` runs before `make test` and
  fails the build if any banned API appears in `Spotiglass/` or
  `SpotiglassTests/`. The driver (`SpotiglassEQDriver/`) is exempt by
  design but is also output-scope only.

- **Driver is signed with the user's Apple Development cert.** Free
  Personal Team is enough on macOS 26 (verified empirically). Developer
  ID + notarisation is the right move for shipping outside the developer
  machine.

- **The `.driver` is installed system-scope.** `/Library/Audio/Plug-Ins/HAL/`
  on macOS 26. The unprivileged GUI process can't write there, so the
  install path is sudo-gated and surfaced as a one-shot user command.

- **Audio path uses an `AudioServerPlugIn`, not `AudioDriverKit`.** ADR-EQ-1
  in `docs/equalizer.md` explains why: DriverKit needs the
  `com.apple.developer.driverkit.transport.coreaudio` entitlement which
  isn't issued to indies.

- **Plugin → GUI IPC uses POSIX shmem + 64-bit atomic seqlock.** ADR-EQ-2
  in `docs/equalizer.md`. CFMessagePort / XPC / Mach-IPC syscalls can't
  be made from the realtime IO callback.
