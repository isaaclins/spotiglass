# Known limitations

- **App Sandbox is disabled** — The Spotiglass macOS bundle ships with `com.apple.security.app-sandbox` set to `false`. This is required for two features that the App Sandbox blocks: (a) writing the merged settings file at `~/.config/spotiglass/settings.json`, and (b) creating a Core Audio process tap on Spotiglass's own PID for the live equalizer. The trade-off is that Spotiglass can read and write outside its container; treat this like any other unsigned macOS dev-mode app and only run binaries you built yourself or trust.
- **Equalizer requires macOS 14.4 or newer and Audio Recording permission** — The live EQ is implemented with `CATapDescription` + an aggregate device + `AVAudioEngine` + `AVAudioUnitEQ`. Process taps are macOS 14.4+ APIs. The first time you toggle the EQ on, macOS prompts to grant **Audio Recording** permission to Spotiglass; deny it and the toggle reverts and the engine reports the error in Settings → Equalizer. The original DRM-protected audio from the Spotify Web Playback SDK is muted at the device level via the tap, and only the EQ-processed copy plays through the system default output.
- **Premium-only playback** — The Web Playback SDK reports `account_error` for non-Premium accounts. Spotiglass shows a clear “Spotify Premium required” style message. Playlist browsing may still work without Premium.
- **Playback bar volume** — The slider adjusts **Spotify Web Playback SDK** output (`player.setVolume`) inside Spotiglass. It is **not** the macOS system output volume; menu bar / Control Center still control overall device level.
- **Playback connects when signed in** — After successful Spotify sign-in, Spotiglass registers the hidden Web Playback SDK device automatically. Use **Reconnect** in the playback bar (or the Command Palette “Connect Playback” command) only when playback drops or errors.
- **Unsigned macOS distribution** — Release and CI artifacts are deliberately unsigned. Notarization and Developer ID signing are out of scope for this repository’s workflows.
- **No backend** — All Spotify traffic goes directly from the Mac client. No Spotiglass server, telemetry product, or cross-machine sync.
- **Single Spotify session** — One signed-in account at a time. To switch accounts: Disconnect (clears Keychain refresh token and local cache), then Connect again.
- **Fixed OAuth loopback port** — Sign-in listens on `127.0.0.1:43824`. Another process binding that port during sign-in prevents the listener from starting; resolve the conflict and retry.
- **Playlist items API limit** — Spotify’s playlist tracks endpoint returns at most 50 items per request. Spotiglass paginates and merges pages; users still see full playlists, but network traffic is chunked accordingly.
- **Liked Songs load cap** — `GET /v1/me/tracks` is paginated the same way, but Spotiglass stops after **20 pages** of 50 (at most **1,000** liked tracks loaded into the UI) so very large libraries do not issue unbounded requests. Spotify’s **total** count still appears in the header when the API reports it; only the loaded slice is playable from this list.
- **Shuffle and repeat** — Controlled via Spotify Web API (`PUT` shuffle/repeat, `GET` player for state). They apply to Spotify’s **active playback device**; Spotiglass sends your Web Playback **device id** when you use the in-app controls. The **Queue** subtitle mirrors repeat mode; **Repeat one** may not show the current track duplicated in **Up next** until Spotify advances playback. Queue order after shuffle comes from Spotify’s queue response on refresh.
- **Artist pages** — Artist detail and discography come from Spotify Web API endpoints (`/v1/artists/...`). In **Development mode**, Spotify may forbid `GET /v1/artists/{id}/top-tracks` (see [Feb 2026 Web API dev-mode changes](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide)); Spotiglass then fills the **Tracks** row from artist-scoped **search** and, if needed, recent **album/single** track lists. **`GET /v1/artists/{id}/albums`** accepts at most **`limit=10`** per request ([reference](https://developer.spotify.com/documentation/web-api/reference/get-an-artists-albums)); Spotiglass uses that page size and follows **`next`**, but **stops after 20 pages** (at most ~200 albums) so large discographies do not trigger long bursts of requests or HTTP **429**. The artist view requests **`album`, `single`, and `compilation`** groups only (not **`appears_on`**), which further reduces page count. Requests use your profile **country** as **market** when Spotify provides it.
- **Queue panel sync** — The in-app **Queue** panel shows “now playing” from live Web Playback state, upcoming tracks from the Web API’s `GET /v1/me/player/queue`, and uses **~4s polling** while the panel is open (Spotify does not push queue changes over the Web API). Changes made in other Spotify clients may lag briefly. **Remove / reorder in queue** is not supported — those controls are not exposed by the Web API for third-party apps.
- **Web API rate limits** — Spotify may return HTTP **429** with `Retry-After` if usage is very high. Spotiglass debounces palette search, caches eligible GET responses in memory and on disk, and avoids extra per-artist requests from search results; very heavy use can still hit Spotify’s limits.
- **In-app lyrics (LRCLIB)** — Synced lyrics come from the third-party **[LRCLIB](https://lrclib.net)** HTTP API (`get-cached` then `get`), not from Spotify. Coverage is community-driven: many tracks have timed lines, some only plain text, and some return nothing. Timing accuracy can vary. The API is documented as beta and may change. Lyrics require network access from your Mac; Spotiglass sends a `User-Agent` identifying the app. This feature is unrelated to Spotify’s own lyrics licensing or catalog guarantees. When a **music** track is now playing or paused with known metadata, Spotiglass **prefetches** LRCLIB results in the background so opening the lyrics overlay usually avoids a loading spinner; the first time on a new track (or after a failed prefetch) you may still see a brief fetch.
