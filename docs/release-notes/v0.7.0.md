The accessibility and translation release. Spotiglass can now be driven entirely from the keyboard, read aloud by VoiceOver, and used in German or Spanish without falling back to English, and the errors it shows are written for people rather than for the network log.

## Everything is reachable from the keyboard

Track rows on Home, Artist and Search only responded to a mouse double-click, and a track selected with the arrow keys in the playlist table could not be played at all, because Return was not handled anywhere. Album cards on an artist page and rows in the queue panel had the same problem. All of those activate from the keyboard now.

Add to Queue and Pin used to exist only in a right-click menu. They are in the Playback menu, acting on the table's selection, with ⌥⌘E and ⌥⌘P.

Help > Spotiglass Help used to do nothing whatsoever, silently. It opens the documentation, and a second item opens the issue tracker.

## VoiceOver

The seek bar announced a percentage but offered no way to change it. The volume slider never said how loud playback was. All ten equalizer faders introduced themselves with the identical label "Band gain", so there was no way to tell 32 Hz from 16 kHz. Explicit and Unavailable badges were never spoken. Breadcrumbs claimed to be buttons but exposed no action. Each of those is fixed, along with command palette rows, queue rows and the Settings profile chip.

## German and Spanish

The app shipped an in-app language picker while large parts of the interface ignored it. The entire Spotify error vocabulary, every empty state in the browser, the loading spinner, the artist header's "followers", and the equalizer's error messages were all hardcoded English.

The audit that was supposed to catch this reported a clean bill of health throughout, because it only looked at string literals handed directly to a UI construct. It now also reads the bodies of `errorDescription`, `userMessage`, `failureReason` and `recoverySuggestion`, and it can see plural entries, which it previously reported as untranslated in every locale. Turning each of those on found leaks that had been invisible: fifteen in the error vocabulary alone.

Counts are pluralized by the catalog now rather than by hand, which is why the Spanish alert no longer reads "canciónes". One concept is named one way per language across every surface.

## Errors written for people

Error copy used to expose HTTP status codes, OAuth scope names and SDK identifiers as if they were ordinary English, and an alert containing a raw HTTP request and response dump could open on you unprompted. The sidebar printed the raw reason phrase "Forbidden". The Connection section reported an OAuth token expiry timestamp.

Developer facts now live in a diagnostics section, next to the message rather than inside it.

## Settings and visual consistency

The Settings window was translucent, which no Mac settings window is. Its sidebar painted its own selection highlight over the one `List` already draws, so the selection stayed bright when the window lost focus. Its search field was hand-drawn, with no clear button, no focus ring and no ⌘F, and it announced itself to VoiceOver as "Account".

The same pinned badge was drawn five different ways, Liked Songs artwork four different ways, and the queue row and track row had drifted into two visibly different copies of the same design. The Recently played shelf cut its last card in half. The scrubber's unplayed track was the app's only `Color.gray` and washed out in light mode.

## Equalizer

It is a graphic equalizer, not a parametric one: ten fixed frequencies with a gain fader each, and the caption said so incorrectly since the feature shipped. The Output device picker rendered blank when the saved device was not connected. The gain readout was boxed to 14 points and would clip at larger text sizes.

## Under the hood

⌘F opened nothing on any existing install: a command was renamed without migrating saved keymaps, which no test could see because tests start from fresh settings. Rebinding "Open command palette" left ⌘K alive as a second, undisclosed trigger.

CI now runs the dead-code detector the repository already had in its Makefile and never invoked, gating on new findings, plus a check for Swift files that are in the repo but in no Xcode target. Two test files had shipped that way, and one of them had stopped compiling entirely.
