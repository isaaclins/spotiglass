The equalizer release. The equalizer has been in Settings for several versions and could never actually install its audio driver on a normal Mac. That is fixed, along with a long list of playback, browsing and settings faults that only appear once you use the app for real rather than in a test.

## Updating from 0.7.0 needs one manual download

Sparkle verifies an update against a public key baked into the copy of Spotiglass you already have. The private half of the 0.7.0 key is no longer available, so this release is signed with a new one. An existing 0.7.0 install will therefore refuse to install 0.8.0 by itself: download the disk image below once, replace the app, and automatic updates resume from 0.8.0 onward.

## The equalizer installs itself now

Installing a system audio plug-in means writing into `/Library/Audio/Plug-Ins/HAL`, which no ordinary app may touch. The previous build asked you to run shell commands with `sudo`. Spotiglass now ships a privileged helper, registers it with macOS's own Service Management framework, and lets the operating system ask for your approval in its own words. There are no Terminal instructions anywhere.

Getting that working end to end on a real machine exposed faults no test could reach, because a test never registers a daemon:

- A daemon that has never been registered reports "not found". The app treated that as fatal, so the very first enable could never install anything.
- The app connected to the helper the instant registration returned, before launchd had the job running, and read the resulting failure as a broken helper.
- Its retry path unregistered an approved service and registered again, which asks you for approval a second time. Because it keyed that decision on a marker written only after a successful install, every enable threw your approval away and asked again, forever.
- The helper carried a debug-only entitlement that launchd refuses to run a daemon with, so registration reported success and the job silently never loaded.
- If Spotiglass was not allowed to run in the background, the switch simply sprang back with nothing on screen. Install failures are deliberately kept out of the settings pane, because macOS's own prompt is normally the whole story. That is right for every case except this one, which only you can resolve. It now says so and offers the trip to Login Items.

## The equalizer tells the truth about its state

It used to report itself live the moment it selected the virtual output device, which happens well before the driver has opened a route to your real speakers. A missing or disconnected target left the pane green while audio went nowhere. Readiness is now reported by the driver itself, and the pane reflects the actual route.

Turning it off used to discard the saved output device even when restoring it failed, which could leave you routed to a virtual device that the app believed was disabled. Disabling is transactional now, and the pre-equalizer device is stored by a stable identifier so it survives a relaunch.

Editing external settings while the app runs reaches the engine, changing the system output device outside Spotiglass is reconciled instead of ignored, the ten band faders are reachable from the keyboard, the editor is disabled while the equalizer is off rather than pretending to accept edits, and preamp values are clamped where they are saved rather than where they are drawn.

## Playback

A second window could not play anything, because the playback host belonged to the first one. Playback started elsewhere on Spotify Connect did not appear in the transport. The scrubber could seek the wrong track if you scrubbed across a track change. Skipping past the end of a queue and rapid play or skip presses could interleave into an inconsistent state. Volume changed on another device did not come back. Disconnecting left work in flight that could resurrect a signed-out session.

The now-playing summary had disappeared entirely, the lyrics button in the transport did nothing when clicked, and Repeat had two competing shortcuts and no single cycling one.

## New

Your library keeps loading as you scroll instead of stopping at the first page. Track options are one menu everywhere, rather than a different subset per surface. Artist pages have selectable rows and play and shuffle actions in the header.

## Browsing, settings and accounts

The sidebar was clipped at narrow window widths instead of collapsing. Two different context menus disagreed about whether a track was liked. Search and Home did not refresh. Removing several tracks from a playlist removed the wrong ones, because batched removals were applied from the front. Liked Songs stopped paginating partway.

Missing Spotify permission scopes were detected only by failing, and a raw 403 was printed into the sidebar. Shortcut conflicts were swallowed silently. Editing one bad field in the keymap discarded the rest of the file. Upgraded installs lost keybindings that a migration should have carried across. The command palette and other transient state leaked between windows.

The in-app language picker is now a dependency the interface observes, so every surface changes language at once instead of some of them waiting for a relaunch.

## Under the hood

The test suite no longer sleeps for fixed durations anywhere; it waits for the condition it actually cares about. Local test runs use the same per-test timeout as CI, so a wedged test fails with a name instead of burning forty minutes. View tests are hosted off screen so no remote view service attaches to them, and the artwork tests no longer read or write your real cache. The audio driver's router has unit tests that run in CI.

Local builds are signed with a stable identity, so the keychain stops asking for your password after every rebuild.
